# StreamSetu: complete architecture

*All apps, every folder, nested and unnested files.* The folder trees and file counts below are generated from `git ls-files` (tracked files only, not build output), so they are exact for the commit they were generated from. The descriptions come from the existing architecture documents (`macos/Docs/`, `android/ARCHITECTURE.md`, `ios/README.md`, `windows/native/README.md`, `docs/`) and from reading the folder and file names. Where something is inferred, not read, the text says so.

Versions at the time of writing: Mac 2.19.0 (build 362, being released), iPhone and iPad 1.4 (build 79), Android and Fire TV 0.27.0, Windows 0.2.0.

## 1. What StreamSetu is

StreamSetu is a **player, not a content provider**. People add their own playlists (M3U, Xtream), media servers (Jellyfin, Emby, Plex), portals and local files. Each app turns those into one local library (movies, series, live channels, a programme guide), plays it with one player that recovers from failures, and keeps favourites, history and settings on the device. There is no account and no server of ours. On the Mac there is also a streaming-services layer (a service's own website inside the app), a Podcasts section and a large Music module.

The five apps are **independent codebases** that follow the same design, the same data rules and the same specifications. They do not share a runtime. The one exception is iPhone and iPad, which compile the platform-neutral Swift files of the Mac app directly.

## 4. What the apps share (contracts, not code)

- **Identity.** An item's id is `<source uuid>|<kind>|<provider id>`, never a list position, a name or a URL (URLs carry rotating tokens). M3U items with no provider id use a hash of `tvg-id`, normalized name and group. Favourites, history, hidden items and renames hang off these ids so a refresh never loses them.
- **Catalogue writes are atomic.** A refresh is validated first and committed in one transaction; an empty refresh (or one far smaller than the last) is rejected, so a good catalogue is never replaced by a bad one.
- **One player with recovery.** One instance, instant switching, retry with backoff that re-resolves the stream URL, one engine fallback on a format failure, no silent switch to another source, no retry on an authorization failure, plain-language errors with logins redacted.
- **Folder privacy.** One visibility rule per surface (history, search, recommendations): a locked folder stays out of recommendations even after a PIN unlock.
- **Smart Mix.** An integer-scored engine with a seeded draw, tested against fixtures in `smartmix/fixtures` on every platform.
- **The opening.** `motion/specification/opening-motion.json` fixes the shared variants and timings; each app's tests read it (Mac, iOS, Android, Windows). The Mac's own story (section 5.8) reads only the variant lengths.
- **Local sync.** Favourites, resume points and collections stay in step between devices on the same network, paired once by comparing six digits (`Services/LanSync` on Apple, `LanSync.cs` on Windows, `sync/` on Android). No server.
- **Host parity.** `Scripts/check-host-parity.py` keeps the lists of allowed hosts the same on every platform.
- **Legal text.** `legal/` is the source of the privacy policy, terms and licences; `legal/sync-legal.py --check` runs inside the Mac build.

## 5. Mac app (`macos/`)

### 5.1 Layers

```
Presentation   SwiftUI views and @Observable view models           Features/
     |
Domain         Entities, protocols, use cases                       Domain/
     |
Services       Sync, search, artwork, playback coordinator,         Services/
               assistant, streaming services, Music, podcasts ...
     |
Data           HTTP client, M3U / Xtream / XMLTV adapters,          Data/
               SQLite (GRDB-free, purpose-built), indexing, cache
     |
External       playlists, Xtream APIs, XMLTV, media servers, public music and metadata services
```

Rules the code enforces (tests and `Scripts/verify-layering.sh`): the UI never downloads or parses; nothing heavy runs on the main thread; user data survives refreshes; sources are untrusted (size limits, scheme checks, XML entity expansion off); playback state lives outside views; Domain, Data, Services, Playback and Security never import SwiftUI.

### 5.2 Start-up and lifecycle

`ReddyApp` (entry; preloads service icons and opening art) creates `AppCoordinator`. `AppCoordinator.boot()` opens and migrates the database **off the main thread**, builds `AppContainer` (the object graph: settings, database, services, playback, parental controls, app lock), then `AppState`. `RootView` draws the content (a loader, the recovery screen if the library cannot open, or `MainShell`) with `OpeningOverlay` in front. The overlay is owned by one process-wide `OpeningCoordinator`, so a rebuilt window or a content change can neither restart it nor keep it on screen. Work that is not needed for the first screens (artwork matching, cloud, backups, resuming the last channel) waits until the opening is gone. `MenuCommands`, `DeepLink` (`streamsetu://add`, `streamsetu://play`) and `AppUpdater` (Sparkle) hang off the same layer.

### 5.3 Data

SQLite in WAL mode behind `DatabaseManager`: one serialized writer and one reader, so a long import never blocks the UI. Search is FTS5 (`search_docs` + `catalog_fts`, prefixes, accent-insensitive). Migrations are versioned with `PRAGMA user_version`, append-only, in `Data/Database/Schema/` (latest `SchemaV27`). Tables include sources, categories, channels, movies, series, episodes, stream variants, the EPG tables (imported under a fresh `import_id` and switched in one transaction), favourites, history, progress, collections, hidden items and the music tables (`DatabaseManager+Music`). `IndexHealthMonitor` checks and repairs the index. Logins live in the Keychain, artwork in a disk cache, preferences in UserDefaults. See `macos/Docs/DATABASE.md`.

### 5.4 Playback

`PlaybackCoordinator` (main actor, outside any view) owns playback; engines sit behind `PlaybackEngine`. **AVPlayer** is primary (HLS, MP4, and raw MPEG-TS through a local HLS bridge, `TSBridge` and `TSSegmenter`); **libmpv** handles MKV, AVI, RTSP, DASH and unusual codecs (bundled; hardened-runtime safe, with scripting disabled). Engine choice is by container, overridable in Settings. A state machine (`idle -> resolving -> preparing -> buffering <-> playing / paused / seeking -> ended / failed`) governs every transition. Extras: sleep timer, radio mode, quality fallback, Multi-View (up to four tiles), catch-up, per-playlist headers, Picture in Picture, AirPlay. See `macos/Docs/PLAYBACK.md`.

### 5.5 Services (the large middle)

`Services/` has 735 files. Subfolders: `Guide` (15), `Hub` (8), `LanSync` (6), `Music` (539), `SmartMix` (13), `Streaming` (40), `Sync` (5). Loose files in `Services/` are the cross-cutting services (catalogue sync, EPG sync, artwork and details, search, downloads, favourites and history, diagnostics, the Setu assistant's engine, router, toolbox and knowledge, podcasts, keyword alerts). `Services/Streaming/` is the streaming-services layer (a service's own website inside the app, with a themed Services panel, per-service settings, and optional page options). `Services/Guide/` and `Services/Hub/` build the programme guide and the metadata hub (one identity per title across sources). `Services/SmartMix/` is the recommendation engine. `Services/LanSync/` and `Services/Sync/` are device sync.

### 5.7 Atlas and the Setu assistant

`Atlas/` (77 files) is a registry of every control and screen with an id, a name, a description and a path (`Declarations/`). It drives the in-app assistant (Setu), Spotlight and the generated coverage document (`docs/assistant-coverage.md`). A scan tool in `macos/Tools/AtlasScan` and a test (`macControlsAreAllMarkedOrExempt`) fail the build if a control has no Atlas id; exemptions are capped and listed in `exemptions.json`.

### 5.8 The opening, Get Set Up and first run

- **Opening** (`Features/Opening/`): `OpeningCoordinator` (one clock, the launch variant, the app-ready hand-off, exactly-once reveal), `OpeningTimeline` (shared, deterministic), `OpeningMacStory` (the Mac's story, a pure function of time) and its renderer and canvas, `OpeningIcons` (the app's own navigation icons, rendered once), `OpeningTheme` (the saved accent, read once per run), `OpeningWatchdog`. The first launch plays the full story on pure black: icons cross one at a time with their names and an accent glow, converge, spin into the StreamSetu symbol, and the name slides out from behind it. Every launch after that plays a short version: the symbol turns once and the name slides out. Reduce Motion shows the finished logo. The text is laid out once and drawn each frame.
- **Welcome and Get Set Up** (`Features/Onboarding/`): the welcome screen (with Skip for now), and a full-window, three-step setup (Music, Podcasts, streaming services) in the saved theme; it waits for the opening and What's New to be gone, and reopens from Help.
- **What's New** is shown once after an update, after the opening.

### 5.9 Design system, themes, localization

`DesignSystem/` (48 files): tokens (`ColorTokens`, typography, spacing), components, modifiers, and the theme palettes (25 themes, a custom theme editor, 21 accents). A test fails the build on literal colours outside the theme. The app's own wording is in English, Hindi and Telugu (`Resources/Localization/{en,hi,te}.lproj`); a test checks that every user-visible literal has Hindi and Telugu.

### 5.10 Security and privacy

Logins in the Keychain (`KeychainManager`, `LocalCredentialStore`, `SecureStorage`); an app lock and a salted-hash PIN with throttling after wrong tries (`PINHash`, `PINThrottle`); parental controls and kids mode; `SourceURLValidator`; `CredentialRedactor` keeps logins out of logs and errors; the built-in API keys are scrambled into git-ignored generated files at build time and a scan blocks any release where a key is visible in a file. App Store privacy answer: Data Not Collected (see `docs/APP-STORE-PRIVACY.md`, `macos/Docs/SECURITY.md`).

### 5.11 Build, sign, update

`swift build` (debug); `Scripts/build-release.sh <version> <build>` builds the universal app (arm64 + x86_64, optionally with libmpv via `bundle-libmpv.sh`); `release-signed.sh` runs the dependency gate, builds, signs with Developer ID, notarizes, staples and makes the DMG; `Scripts/dev/mac-build.sh` and `mac-install.sh` build and install locally. Sparkle checks the feed (`SUFeedURL` = the raw `appcast.xml` on GitHub), verifies the EdDSA signature against `SUPublicEDKey`, and offers the universal DMG.

## 6. iPhone and iPad (`ios/`)

SwiftUI, iOS 18+. **It does not duplicate the engine.** `ios/SharedSources.txt` lists the platform-neutral files of the Mac app (database, parsing, sync, search, guide, playback logic, settings) that are compiled straight into the iOS app; `ios/Scripts/generate-project.py` writes `StreamSetu.xcodeproj` from that list (the project is never edited by hand). ## 7. Android phone and tablet, and Fire TV / Android TV (`android/`)

One Kotlin codebase, two experiences (touch layouts for phone and tablet, remote-first layouts for television), built as **one APK** that is published under two names (`StreamSetu-Android-<v>.apk`, `streamsetu-tv-<v>.apk`). It mirrors the Apple apps' design but shares no code with them.

**Gradle modules**

| Module | Role |
|---|---|
| `core-model` | Plain data classes, sorting and capability models, playback preference enums |
| `core-security` | Android Keystore credential store (AES-GCM); passwords never reach the database or logs |
| `core-network` | One OkHttp client; M3U, Xtream and XMLTV parsers (pure logic, unit tested) |
| `core-database` | Room: catalogue, libraries, folder arrangements, progress, derived content identity, the metadata hub, details-service tables |
| `core-preferences` | App settings (playback), UI preferences, parental controls |
| `core-media` | `PlaybackController` (one coordinator), ExoPlayer and MPV engines, recovery policy |
| `core-ui` | Motion tokens, reduced-motion handling, frame monitor |
| `data` | Repositories (library, catalogue, browse, folders, search, user, source), sync, EPG, maintenance (backup, diagnostics, cleanup), Smart Mix |
| `app` | Hilt wiring, navigation, screens, opening, sports, recording, in-app updater, diagnostics |

**Data flow:** playlist -> `SyncService` -> Room (one transaction, together with the search index) -> DAO `Flow` -> repository -> ViewModel `StateFlow` -> Compose. Every query is already limited to the open library through `LibraryRepository.sourceIds`. **Playback:** the UI sends commands to `PlaybackController` and watches its state; it picks the engine, spaces connections on one-connection accounts, retries (1, 2, 4, 8, 15 s), falls back once, saves progress only for the verified session, and handles leaving and returning to the app. **Updates:** `update/UpdateManager.kt` reads the public GitHub release list, downloads the right file for the device and checks its SHA-256 against the release notes. **Search:** `GlobalSearch` and `SmartSearch` (understands "hindi movies 2024"). See `android/ARCHITECTURE.md` and `SPEC-STATUS.md`.

## 11. Cross-cutting design

- **Privacy by design.** No account, no analytics, no ads; everything stays on the device. Only ids go to the artwork, episode-data and schedule services, and only titles and years to the details service (declared as Other User Content, not linked, not used for tracking). A secret scan and a manifest check gate every release.
- **Theming.** The Apple apps and Android share one palette family (near-black, accent per theme). The Mac and iOS read the theme from one token layer; a test blocks literal colours elsewhere.
- **Localization.** English, Hindi and Telugu on the main screens of each app.
- **Accessibility.** Reduce Motion substitutes (the opening becomes a still logo), screen-reader labels, and text sizes that suit a television.
- **Reliability.** Atomic catalogue commits; a recovery screen that repairs a damaged library without deleting it; progress written only for the verified session; engine fallback changes the player, never the provider stream.

## 12. Build, test, release pipeline

| Step | Where | What runs |
|---|---|---|
| Unit and integration tests | `macos` (`Scripts/test-serial.sh`, about 6,190 tests, ten minutes), `android` (`./gradlew testDebugUnitTest`, Robolectric), `ios` (`Scripts/test-ios.sh`), Windows (`StreamSetu.Core.Tests`) | Timing-sensitive tests run one at a time on purpose |
| Static gates | `Scripts/check-host-parity.py`, `audit-dependencies.py --strict`, `check_no_secrets.py`, the Atlas scan, `verify-layering.sh`, the theme-literal scan | Fail the build, not a warning |
| Build | `macos/Scripts/release-signed.sh` (Mac), `android/build-release.sh` (APK), `ios/Scripts/testflight.sh` (iOS) | Mac: universal, Developer ID signed, notarized, stapled |
| Verify | `Scripts/verify-release-artifacts.sh` | Notarization, signature, version, architectures, privacy manifest, smoke test, signer pin, permissions, checksums, committed code |
| Publish | `Scripts/release.sh <tag> <notes>` | Verify -> upload as draft -> check the upload -> publish -> Mac update feed -> README table -> website. `ANDROID` unset makes a Mac-only release. Tested by `Scripts/test-release-gates.sh` |
| Update | Sparkle (Mac), `UpdateManager` (Android), Releases check (Windows), App Store (iOS) | Every update is checked against a signature or SHA-256 |
