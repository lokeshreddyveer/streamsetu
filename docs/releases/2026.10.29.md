## App DNS (Settings, Network)

- Off by default. Turn it on, pick a provider, and press **Test App DNS**: it checks your playlist and guide servers as well as a public name and says whether the device's own DNS could resolve them.
- With it on, remote names are never quietly sent to the device's DNS; a lookup that cannot be answered fails and says so. Names on your own network (`.local`, single-label names, private addresses) keep using the device's DNS, which you can switch off.
- A public name that an encrypted resolver answers with a private address is refused (DNS rebinding).
- The DNS provider you choose can see the host names StreamSetu looks up, and may be able to tell which IPTV or CDN service you use from them. It does not receive passwords, stream paths or viewing history.
- DNS fixes DNS blocking only. It cannot get past IP blocking, routing problems, server outages or geographic limits.
- **Coverage.** Android, Fire TV and Android TV: playlists, guides, artwork, search, health checks and Media3 playback. iPhone, iPad and Mac: everything that uses Apple's networking, which includes Apple's player. On the Mac the MPV player (used for MKV and similar files) still uses the system DNS. On Apple devices Private Relay or a system-wide encrypted DNS profile can take precedence over the provider you pick. Native VLC/MPV engines have not been checked.

## Mac and iPhone

- **Library recovery.** If the library cannot be opened you can **Repair Library** (keeps your data) or **Start Fresh** (asks first and says what would be lost). The damaged library is always kept in a Recovery folder.
- **Backup restore** is one step: if anything fails, nothing is changed, and restoring the same backup twice adds nothing twice.
- **iPhone Search** shows every kind of result the same way, puts an exact title first, and says whether it is loading, found nothing or failed. **Live TV** shows how many channels there are.
- **Large text.** Text sizes above the old limit now work: rows reflow and the Guide becomes a plain list per channel.
- **Settings.** Backup and Storage are in one place, and failures that used to be ignored now show a message. Proxy and VPN explain that StreamSetu provides no app-only VPN.
- **Network safety.** Only the playlists you add may use plain http; every service StreamSetu itself talks to must use https. A login typed for an http server asks first. Logins are not sent on to another server by a redirect.
- **Problem reports** are off until you turn them on; the privacy policy now says so from its first paragraph.
- **PIN codes** are stored with a slow salted hash and upgraded the next time they are entered.

## Known limits

- The iPad uses the iPhone layout; a proper iPad layout is not in this release.
- The new screens were compiled and unit-tested but not all looked at on a device. The Assistant playback-watch unit test occasionally fails when the whole suite runs under heavy load and passes on its own.
- The App DNS comparison with the device's own DNS is only shown while App DNS is off (with it on the device lookup would itself go through App DNS).
- Android 5.1 devices cannot save a login (unchanged).
